## 2026-11-08 · Company Claude Code (polish)
- **Faster pages: the language picker no longer downloads all translations.** It used to read the four language names from the full dictionaries, so every page with the picker sent all four complete translation files to the browser. The names now come from a small list in `src/i18n/names.ts`; keep it in sync with `languageName` if a language is ever added. About 40 KB less JavaScript on each of those pages (from the build output): landing 146 → 106 KB, login 213 → 173 KB, sign-up 146 → 106 KB, careers page 138 → 97 KB, candidate page 141 → 101 KB. Why: quicker loading, especially on phones.
- **Lighter sign-up and login photos.** The side photos on sign-up now go through the same optimised image component as the landing page (`Photo`, next/image), so the browser gets a resized, compressed version instead of the full 140–440 KB JPEGs. Because those images load lazily, phones (where the panel is hidden) don't download them at all. The login, forgot-password and reset-password pages no longer force-preload their side photo, which phones never show. Not checked in a browser: these pages need the database connection to run locally. Why: about 1 MB of unused or oversized photos on the sign-up flow.
- **Mobile landing page: Log in and language.** On phones (under 640px), "Already have an account? Log in" and the language picker now sit just below the hero buttons, using existing texts. The phone header itself is unchanged: a globe button there pushed "Empieza a contratar" onto two lines in Spanish, so I didn't put it there. From 640px up the header shows the language picker and Log in (Log in used to appear only from 768px). Checked in the browser at 375px (Spanish) and 640px (Spanish and French): one-line header, no sideways scrolling. Why: returning users on phones had to scroll to the footer to log in or change language.
- **Grammar and wording slips.**
  - Singular/plural: "1 applicants", "1 days left", "1 roles planned", "1 open role(s)" now read "1 applicant", "1 day left", and so on, in all four languages. New `…One` keys, picked by a small `plural()` helper in `src/i18n/index.ts` that follows each language's rule (French uses the singular for 0 too).
  - French: "offre" is now used everywhere for an open role; pricing and billing used to say "annonce". "Annonce" stays where it means the written job ad.
  - German and French: one Ask-your-pipeline suggestion used informal "du"/"tu"; it's now a question like the others.
  - German: "Demo-Bereich" → "Demo-Workspace" (as everywhere else), and every "…" now has a space before it, like the rest of the file.
  - Plan numbers on the billing page follow the user's language (1,000 / 1.000 / 1 000) instead of the browser's.

  Why: small errors that make the product look unfinished.
- **Search engines and link previews.** Browser tabs and Google show titles and descriptions in the visitor's language (`meta.*` keys), with "· HireKit" after page names (Log in, Sign up, password pages, Dashboard). Careers and job pages keep the company's own title ("Karriere bei Northwind Labs", no HireKit suffix). Links shared on LinkedIn, Slack or WhatsApp now show a preview card; the image is the tour video poster in the visitor's language (`/video/tour-poster-{lang}.jpg`). I didn't use the intro poster because its ES/DE slogans are in the suggestion below. New `robots.txt` (keeps the dashboard, APIs and password reset out of search) and `sitemap.xml` (landing page, sign-up and every careers page with open roles; read through the normal public client, no admin key). Widget pages are marked "noindex" so Google doesn't list them as copies of the careers pages, and they tell screen readers their language when the widget is set with `data-lang`. Checked locally: German titles and preview tags, French 404 page, robots and sitemap. Why: shared links had no preview and careers pages showed English titles to everyone.
- **Accessibility.** Sign-up fields (company, website, work email, password) now have real labels, so screen readers name them and clicking a label focuses its field; the chip choices and colour swatches are named groups. Colour buttons read "Colour 1, 2, 3…" in the user's language instead of hex codes (sign-up and Settings), and Settings swatches say which one is selected. The team-notes box, the "Draft with AI" notes box and the custom meeting-link field have names. Save results and errors (notes, settings, re-screen, interview booking, billing) are announced. The "Upload a PDF" / "Browse" buttons show the yellow keyboard outline when focused. The landing page menus, the widget frame and the iframe snippet in Settings have translated names (`nav.mainMenu`, `nav.footerMenu`, `dash.settings.iframeTitle`, `useColour`); `public/widget.js` keeps a small four-language copy of the frame title because it runs on the company's own site. The forgot/reset password pages were already labelled correctly. Why: keyboard and screen-reader users couldn't use parts of the main sign-up flow.
- **English-only messages now in all four languages.** The landing page "Try it" errors (`tryIt.errors.*`), sign-up errors (`auth.signup.errors.exists`, `companyFailed`; the rest reuse existing keys), dashboard errors from the job form, AI writer, re-screening, settings and Ask your pipeline (`dash.errors.*`), the "Page not found" page (`notFound.*`), the requirements example in the job form (`jobs.form.requirementsPh`) and "30 min" in interview booking (`schedule.minutes`). Raw technical database messages are no longer shown to users; they see a clear "wasn't saved" message instead. Only the wording of messages changed, not how sign-up works. Why: German, Spanish and French users were seeing English at key moments.
- **Loading placeholders and a friendly error page.** Grey placeholders in the shape of the page now show while the dashboard, careers page and website widget load (the careers page and widget can take a few seconds the first time they're translated). When a page fails, visitors see a branded "Something went wrong" page with "Try again" and a way back, in their language, instead of Next.js's plain English crash screen; in the dashboard the menu stays visible. New files: `src/app/error.tsx`, `src/app/dashboard/error.tsx`, `src/app/dashboard/loading.tsx`, `src/app/careers/[slug]/loading.tsx`, `src/app/embed/[slug]/loading.tsx`, `src/components/ErrorView.tsx`, `src/components/careers/JobListSkeleton.tsx`. New keys `loading` and `errorPage.*` in EN/DE/ES/FR. Why: blank screens looked broken.
- **No more spinners that never stop.** If the connection drops or the server fails mid-request, these now stop loading and show a short message in the user's language instead of hanging: Ask your pipeline, Settings save, job save and "Draft with AI", notes save, re-run screening, plan/checkout buttons, interview booking, the free-slot lookup ("Checking your calendar…"), sign-up, and the new forgot-password and reset-password forms. New messages in EN/DE/ES/FR (`dash.errors.generic`, `dash.settings.failed`, `dash.ask.failed`, `auth.forgot.failed`, `auth.signup.errors.failed`). Why: a dropped connection used to freeze these screens until a page reload.
- **No more silent save failures in the dashboard.** If moving a candidate to another stage fails, the dropdown goes back to the real stage and says the change wasn't saved (it used to show the new stage anyway). Opening/closing a job and deleting a job now report database errors instead of pretending they worked; the delete button greys out while it runs. Cancelling an interview now asks "Are you sure?" first, can't be double-tapped and shows an error if it fails. New messages in EN/DE/ES/FR (`dash.errors.saveFailed`, `dash.schedule.confirmCancel`, `cancelling`, `errors.cancel`). Why: recruiters could believe a change was saved when it wasn't.
